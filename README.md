# ZeroHub 1.0.0

ZeroHub — самостоятельный сервер для работы с ИИ-агентами с ПК, ноутбука и телефона. Он объединяет проектные диалоги, Google Antigravity CLI, OpenAI Codex, Claude Code и OpenRouter. Доступны память проектов, журнал диалогов, голосовой ввод на CPU и общие проекты с разграничением прав и Docker-песочницей.

## Требования

- Windows 11 или Linux с Python 3.11+ и Git. Для установки зависимостей нужен доступ к PyPI.
- CLI и учётные записи выбранных провайдеров настраиваются отдельно. Для Docker-песочницы нужен Docker, а на Windows также WSL2.
- HTTP по умолчанию использует порт `8765`, встроенный HTTPS — `8766`. Данные хранятся в `data/`, `users/` и `shared_projects/` относительно каталога установки.

## Windows

В PowerShell из каталога клона выполните:

```powershell
git clone https://github.com/atomexpert/ZeroHub.git
Set-Location ZeroHub
powershell -ExecutionPolicy Bypass -File .\install_windows.ps1
```

Установщик создаёт ярлык **ZeroHub** на рабочем столе и запускает сервер. Адрес на ПК — `http://127.0.0.1:8765`. Для первого входа используйте имя `admin` и пароль из `data/FIRST_RUN_CREDENTIALS.txt`. При необходимости задайте `$env:HUB_INITIAL_PIN` до первого запуска.

## Linux VPS

Выполните под обычным пользователем с доступом к `sudo`:

```bash
git clone https://github.com/atomexpert/ZeroHub.git
cd ZeroHub
bash install_linux.sh --systemd
```

Установщик создаёт виртуальное окружение и регистрирует `zerohub.service`. Статус и логи доступны через `systemctl status zerohub` и `journalctl -u zerohub -f`. Для фонового запуска без systemd опустите `--systemd`. Сервер можно запустить вручную через `bash start_hub.sh` и остановить фоновый экземпляр через `bash stop_hub.sh`.

Для Docker-песочницы выполните `bash setup_sandbox_linux.sh`. Если установщик добавил пользователя в группу `docker`, откройте новый сеанс и штатно перезапустите сервис, чтобы процесс получил членство в группе.

## Телефон и ноутбук

- В одной Wi-Fi сети откройте `https://<LAN-IP-ПК>:8766`. Проверьте разрешение порта в локальном файрволе. Для установки PWA и использования микрофона используйте HTTPS с сертификатом, которому доверяет устройство.
- Для удалённого доступа установите Tailscale на сервер и клиентские устройства. Откройте адрес сервера в tailnet или настройте HTTPS через Tailscale Serve.
- Для собственного домена направьте DNS на VPS, откройте порты 80 и 443 и сохраните следующий пример под именем `Caddyfile`. Caddy автоматически выпускает HTTPS-сертификат и проксирует WebSocket.

```caddyfile
hub.example.com {
    reverse_proxy 127.0.0.1:8765
}
```

Для Caddy на той же машине задайте в `.env` `HUB_HOST=127.0.0.1`, `HUB_HTTPS_PORT=0` и `HUB_PUBLIC_URL=https://hub.example.com`, затем примените настройки штатным перезапуском.

## Обновления и релизы

Пользователям публичного зеркала токен GitHub не требуется. В Настройках администратор может открыть **Центр обновлений**, проверить доступную версию, прочитать список изменений и установить релиз. Если идут генерации, Центр запросит подтверждение принудительного обновления. После установки браузер дождётся запуска новой версии и обновит страницу. Готовность сервера показывает `GET /api/health`.

Перед установкой клиент сохраняет горячую копию SQLite в `backups/` рядом с базой, а правки отслеживаемых файлов — в Git stash. Ключ публикации используется только на стенде автора. Его можно задать в локальном `.env` или через административный маршрут `PUT /api/updates/publisher-config`.
